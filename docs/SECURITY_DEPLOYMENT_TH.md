# การอัปเดตความปลอดภัย

## ขอบเขต

ไม่ได้เปลี่ยนบทบาทหรือขอบเขตสิทธิ์ผู้ใช้ และยังดูผลแล็บย้อนหลังทั้งหมดได้
ไม่ได้เปลี่ยน MD5 ของระบบบัญชีโรงพยาบาล ต้องประสานเจ้าของระบบเพื่อย้ายไป SSO หรือ password hashing ที่เหมาะสมก่อน

## ก่อนนำขึ้นเซิร์ฟเวอร์

- สำรองโค้ดและฐานข้อมูล ทดสอบด้วยฐานข้อมูลแยกจากฐานจริง
- ต้องมีตาราง `system_audit_logs` จาก migration เดิม ไม่ต้องสร้าง migration ใหม่สำหรับชุดนี้
- ประวัติการแก้เชื้อเริ่มเก็บเป็นเหตุการณ์ตั้งแต่ติดตั้งชุดนี้ ไม่สามารถกู้ประวัติก่อนหน้าจากข้อมูลสถานะล่าสุดได้
- ตั้ง `SESSION_LIFETIME=60` และ `SESSION_IDLE_TIMEOUT=60` ใน `.env` ของแต่ละเครื่อง
- ตั้ง `TELEGRAM_NOTIFY_ENABLED=false` และคง `LAB_NOTIFICATION_ENABLED=false` จนอนุมัติเงื่อนไขส่งข้อมูล
- หลังเปลี่ยน config ใช้ `php artisan config:cache` ในช่วงเวลาที่เหมาะสม ไม่ใช่การ migrate
- ติดตั้งแพ็กเกจตาม `composer.lock` ด้วย `composer install --no-dev --prefer-dist --optimize-autoloader` และเปิด GD ใน PHP CLI/IIS ให้ถูกต้อง ห้ามใช้ composer update บนเซิร์ฟเวอร์เพื่อสุ่มเลือกเวอร์ชันใหม่
- ชุดนี้อัปเดต Laravel เป็น 12.69.1 และ dependency ที่เกี่ยวข้อง 22 แพ็กเกจ ผ่าน automated tests หลังอัปเดต แต่ยังต้องทำ UAT บนเซิร์ฟเวอร์ทดสอบ
- อย่าใช้การทดสอบหรือ migrate:fresh กับฐานข้อมูลที่เครื่องพัฒนาและเซิร์ฟเวอร์ใช้ร่วมกัน

## HTTPS ต้องตั้งค่าที่ IIS

ติดตั้ง certificate ที่เครื่องลูกข่ายเชื่อถือได้และผูก HTTPS binding ก่อน ทดสอบเข้าเว็บด้วย HTTPS แล้วจึงตั้ง `SESSION_SECURE_COOKIE=true`, เปลี่ยน APP_URL และ redirect HTTP ที่ IIS
ห้ามเปิด Secure cookie ขณะที่ยังเข้าเว็บผ่าน HTTP เพราะผู้ใช้จะรักษา session ไม่ได้
แยกตรวจ HSTS, firewall, สิทธิ์ DB และ document root ให้ชี้เฉพาะ `public` บนเซิร์ฟเวอร์จริง

## ตรวจรับ

เพิ่ม `package-lock.json` และตรวจ npm dependency แล้ว แต่ไฟล์ JavaScript ที่หน้า Blade โหลดจาก CDN เป็นคนละส่วนกับ npm lockfile จึงยังต้องวางแผนย้ายเป็นไฟล์ local/ตรึงเวอร์ชันพร้อมตรวจหน้าจอ ไม่ควรตีความว่า npm audit ครอบคลุม CDN ทั้งหมด

- เกินเวลาที่ตั้งต้องเข้าสู่ระบบใหม่; polling check-session ไม่ต่ออายุการใช้งาน
- เติม เปลี่ยน และล้างเชื้อ ต้องมีประวัติแยกทุกเหตุการณ์ พร้อมค่าก่อน–หลังและผู้กระทำ
- ถ้าบันทึก audit ไม่ได้ การแก้เชื้อต้อง rollback
- เมื่อ notify ปิดต้องไม่ส่งข้อความ; เมื่อเปิดส่งเฉพาะ allowed=1 และ is_active=1
- จำกัดสิทธิ์อ่าน log และสำรอง audit ไปแหล่งที่ผู้ดูแลแอปแก้ย้อนหลังไม่ได้ตามนโยบายองค์กร

ยังไม่ถือว่าเป็นการรับรองความปลอดภัยหรือผล pentest บนเซิร์ฟเวอร์จริง
